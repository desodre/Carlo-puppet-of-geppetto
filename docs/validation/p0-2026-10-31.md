## Comandos reproduzíveis

```sh
cargo fmt --all -- --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
python3 -m unittest discover -s tools -p 'test_*.py' -v
python3 tools/build_android.py --output dist
python3 tools/smoke_android.py --serial emulator-5580 \
  --manifest dist/manifest.json --output results/p0-smoke
```

Os checks host executaram 10 testes Rust e 12 testes Python. Os testes Python
cobrem sessão (quote, hash, recusa física, colisão, falha e timeout) e política de
aceite/reabertura de pais. O smoke Android cobre diagnóstico, versão e serve.

Para reproduzir o timeout, compile `tests/fixtures/slow_command.rs` com `rustc`
para a ABI do emulador, usando o mesmo linker/target NDK e alinhamento do build.
Crie uma cópia de `dist/manifest.json` apontando o artefato dessa ABI para o
executável de fixture e seu SHA-256. Passe esse manifesto com
`--timeout-manifest` ao smoke. A fixture dorme por no máximo 60 segundos; o helper
deve encerrá-la antes desse prazo.

O comando de diagnóstico não é servidor nem teste de desempenho. Nenhum teste em
aparelho físico foi executado. A automação de issues preparada nesta entrega usa
GITHUB_TOKEN e só passa a atuar após o workflow entrar em `main`.
